# Cloudflare Tunnel (optional remote access)

Cloudflare Tunnel provides an outbound-only connection from this machine to
Cloudflare's edge. It removes the need for router port forwarding. It does **not**
provide compute: every token is generated by llama.cpp on this machine.

> The tunnel targets the **public inference listener** only. The admin dashboard
> and control API live on a different loopback listener and are not reachable
> through the public hostname.

## Prerequisites by mode

| Mode | Account | Domain | Result |
|---|---|---|---|
| Local only | no | no | API on `127.0.0.1:8000`; default |
| Quick tunnel | no | no | ephemeral `https://*.trycloudflare.com`; changes every restart |
| Named tunnel | Cloudflare account | domain on Cloudflare | stable custom hostname, for production |

A named tunnel requires a domain whose DNS is managed by Cloudflare. You choose a
public hostname (for example `llm.example.com`) and route it to
`http://127.0.0.1:8000`. Cloudflare's "managed" hostname must still belong to a
zone in your account. Quick tunnels are the only path that works without a domain.

## 1. Install cloudflared

Linux:

```bash
./scripts/install_cloudflared.sh
```

macOS:

```bash
brew install cloudflared
```

Windows:

```powershell
.\scripts\install_cloudflared.ps1
# or: winget install --id Cloudflare.cloudflared
```

Manual downloads:
<https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/>

If the binary is elsewhere, set `MS_CLOUDFLARE_BIN=/path/to/cloudflared`.

## 2. Quick tunnel (no account)

Dashboard → **Remote access** → **Quick tunnel** → **Start quick tunnel**.

Or:

```bash
curl -X POST http://127.0.0.1:8001/admin/api/remote/start \
  -H "Authorization: Bearer $ADMIN_KEY" \
  -H "Content-Type: application/json" \
  -d '{"mode":"quick"}'
```

Response includes `public_url` and `api_base_url`, for example:

```json
{
  "running": true,
  "public_url": "https://random-words.trycloudflare.com",
  "api_base_url": "https://random-words.trycloudflare.com/v1"
}
```

Client configuration:

```text
Base URL: https://random-words.trycloudflare.com/v1
API Key:  <inference key>
Model:    auto
```

Limitations: no uptime guarantee, URL changes on restart, not for production. The
gateway still authenticates every request.

## 3. Named tunnel (stable domain)

### Create the tunnel in Cloudflare

1. Log in to Cloudflare Zero Trust → **Networks → Tunnels**.
2. **Create a tunnel** → Cloudflared → name it (e.g. `local-llm`).
3. Copy the **connector token**.
4. Add a **Public Hostname**:
   - Subdomain: `llm`
   - Domain: your Cloudflare-managed zone
   - Service: `HTTP` → `127.0.0.1:8000`
   - Do **not** route `/admin` to the admin port. The public listener does not
     serve admin routes anyway, but keep the architecture clean.
5. Optionally configure an Access policy. ModelSwitch API keys are still required;
   Cloudflare Access is defense in depth, not a replacement.

### Start it

Preferred: environment variable, never argv or source control.

```bash
export CLOUDFLARE_TUNNEL_TOKEN='eyJhIjoi...'
export MS_CLOUDFLARE_PUBLIC_URL='https://llm.example.com'
./scripts/start.sh
```

Dashboard → Remote access → **Named tunnel**:

- paste connector token (kept in memory for this process)
- public URL (e.g. `https://llm.example.com`)
- tunnel name label
- start

The token is passed to `cloudflared` through `TUNNEL_TOKEN` in its environment,
not on the command line. It is not logged. Dashboard-entered tokens are not
persisted; set `CLOUDFLARE_TUNNEL_TOKEN` for automatic restarts after a gateway
restart.

API:

```bash
curl -X POST http://127.0.0.1:8001/admin/api/remote/start \
  -H "Authorization: Bearer $ADMIN_KEY" \
  -H "Content-Type: application/json" \
  -d '{"mode":"token","token":"eyJ...","public_url":"https://llm.example.com"}'
```

Public base URL:

```text
https://llm.example.com/v1
```

## 4. Health and recovery

Dashboard → Remote access shows process state, public URL, last health check,
connector log tail and admin exposure status.

Endpoints:

```bash
curl -H "Authorization: Bearer $ADMIN_KEY" http://127.0.0.1:8001/admin/api/remote
curl -X POST -H "Authorization: Bearer $ADMIN_KEY" http://127.0.0.1:8001/admin/api/remote/check
curl -X POST -H "Authorization: Bearer $ADMIN_KEY" http://127.0.0.1:8001/admin/api/remote/restart
curl -X POST -H "Authorization: Bearer $ADMIN_KEY" http://127.0.0.1:8001/admin/api/remote/stop
```

If the public URL returns 530/1033:

1. Run the health check. It distinguishes connector failure from origin failure.
2. Confirm `http://127.0.0.1:8000/healthz` works locally.
3. Restart the tunnel.
4. Read `data/logs/cloudflared.log` for credential/DNS/edge errors.
5. For named tunnels, confirm the public hostname's service is
   `http://127.0.0.1:8000` and DNS is proxied by Cloudflare.

## 5. Security checklist

- Keep `MS_ADMIN_HOST=127.0.0.1` (or a private interface). Never tunnel the admin
  port.
- Use inference keys with model scopes and TPM/RPM limits for remote clients.
- Rotate any key that may have been exposed; key rotation is immediate.
- Prefer named tunnels with Cloudflare Access for production.
- Quick tunnels are ephemeral and should be treated as public endpoints that
  happen to require a secret.
- The gateway exposes `/healthz` and `/readyz` publicly; they contain no secrets.
- `/docs` is public on the inference listener; it describes only the public API.
